# Good Practices for Software Development

## Review Questions

### Question 1: Which point(s) were new to you?

A few points were new to me:

- Over-communicating when there is a delay, technical issue, or change in requirements instead of waiting until the last moment.
- When asking for help, I should clearly explain the problem, what I tried, and what the actual error is instead of simply saying that something is not working.
- Using screenshots, diagrams,or code snippets can make technical questions much easier to understand.
- Keeping questions together in one message instead of sending many separate messages helps avoid disturbing teammates repeatedly.
- Protecting concentration during work is important. 

### Question 2: Which area do you think you need to improve on? What are your ideas to make progress in that area?

I think I need to improve mainly in communication when I am stuck.

Sometimes I may focus too much on trying to solve a problem myself and delay asking for help. When I finally ask, I should make sure that I provide enough information for the other person to understand the problem quickly.

To improve this, I will:

1. First try to understand and reproduce the problem.
2. Check the error message carefully.
3. Try a few possible solutions myself.
4. Note down what I have already tried.
5. Ask a specific question instead of simply saying that something is not working.
